# 决策算法说明

依靠该决策算法，在老虎机过三关的情况下，救济院通关分数最高可达 **53,000 分**。

复杂度只计算组合搜索、排序和动态规划，网络推理与外部模拟的耗时另计。

## 决策总览

| 决策 | 核心算法 | 目标 | 实现 |
| --- | --- | --- | --- |
| 刷开局、寻路 | DFS + 回溯 | 找到满足格子下限和首领名单的路径 | [opening.cpp](../src/opening.cpp) |
| 自动编队 | 组合枚举 / 随机束搜索 + Critic（阵容评分网络）排序 | 在有限候选中选出可用阵容 | [inference.cpp](../src/inference.cpp)、[team.cpp](../src/team.cpp) |
| 模拟器验证 | 模拟后稳定排序 + 逐队选择 | 优先胜利，再比较返秒 | [simulator.cpp](../src/simulator.cpp) |
| 角色三选一 | 共享基线 + 加权边际增益 | 选择最能改善后续关卡准备度的角色 | [recruitment.cpp](../src/recruitment.cpp) |
| 商店 | 子集枚举 + 记忆化期望 DP | 最大化预期商品得分，同分最小化花费 | [shop.cpp](../src/shop.cpp) |
| 刷分 | 线性计分 + 阈值判断 | 预测通关分是否达到目标 | [score.cpp](../src/score.cpp) |
| 自选、印记、遗物、事件、清票 | 优先级扫描 / 字典序比较 / 查表 / 轮转 | 按配置直接决策 | [decisions.cpp](../src/decisions.cpp) |

## 1. 刷开局与寻路：带计数约束的路径搜索

地图是有向图，格子是点，可走关系是边。状态为：

```text
(当前格子 u，各类格子还缺多少 remaining，当前路径 visited)
```

经过一个格子，就把相应缺额减一，减到零为止。DFS 到最后一列时，检查缺额是否全为零、首领是否在允许名单中；回溯时恢复当前路径的访问标记。

```text
dfs(u, remaining):
    计入 u 的格子类型
    若 u 在最后一列：返回“缺额全为零且首领符合要求”
    按邻接顺序递归后继，找到可行分支就返回成功
    所有分支失败，返回失败
```

- **刷开局**：逐层判断是否存在可行路径；所有需要检查的楼层都通过才接受。失败后，根据已尝试次数返回重试或停止。
- **寻路**：先用已踏破格子抵扣下限，再依次检查当前位置的后继，返回第一个能继续满足条件的格子。

DFS 返回第一条符合条件的路径。设路径长度为 `L`，遍历的分支路径数为 `P`，最坏约 `O(P·L)`，递归空间为 `O(L)`；分叉多时 `P` 可指数增长。实现另有搜索步数限制。寻路失败时返回无动作。

## 2. 自动编队：生成候选，再评估排序

> **注意**：当前模型只适合普通关卡、部分EX关卡，对于机器人EX、部分第三层首领效果不佳，仍需优化。

### 候选生成

设模型支持且当前可用的角色数为 `n`，候选数为 `K`，每队五人。

1. 若 `C(n,5) < K`，枚举全部五人组合。
2. 否则用**随机束搜索（Stochastic Beam Search）**生成最多 `K` 套候选。

束搜索逐个位置选人，每一步批量计算下一位角色的概率，用 Gumbel 扰动和父子优先级校正保留前 `K` 个前缀，五步后得到完整队伍。队内强制按角色 ID 递增选取，因此同一五人组合只有一种表示，单次生成不会重复。

枚举实现约 `O(n·C(n,5))`。束搜索中，设模型词表大小为 `V`，扩展与截断的复杂度约 `O(5·K·V·log K)`。它按模型概率抽取候选，后续由 Critic 判断质量。

### Critic 排序

Critic 预测胜利及不同耗时区间的概率，由此计算胜率和胜利条件下的预计耗时。排序规则为：

1. 胜率达到 90% 的队伍排在前面，先比较预计耗时，越短越好；耗时相同再比较胜率。
2. 其他队伍先比较胜率，越高越好。
3. 若仍相同，再比较目标时间内通关概率、预计耗时和角色 ID 顺序。

候选排序为 `O(K log K)`。

### 多队与失败重试

单队且有一至五名可用角色时，直接使用现有角色。首领需要多队时，每选出一队就移除其成员，再为下一队生成候选；遇到已失败的完整编队时回溯换方案，并由内部检查预算控制搜索量。第三层队数可配置为 1/2/3，第五层为三队。

回溯按候选顺序寻找可用组合。失败记录排除的是完整编队，其中的角色仍可用于其他组合。已有失败记录后，若没有新组合可试，或失败次数超过重试上限，就执行配置的“重新开局”或“转人工”。

### 可选模拟器验证

Critic 排序后，将多套候选交给模拟器，按以下顺序稳定排序：

```text
模拟胜利优先 → backTime 较大优先 → 保留原 Critic 顺序
```

只有一套候选时跳过模拟。没有可用的模拟胜利结果时，保留 Critic 顺序。多队首领在剩余角色池上逐队重复这个过程，同一请求中的相同队伍复用模拟结果。

## 3. 角色三选一：比较加入角色后的边际增益

设已有角色集合为 `U`，三个候选为 `a、b、c`。参与评估的目标来自后续首领和可能遇到的 EX，每个目标有可配置权重 `w[t]`；权重为零的目标不参与评估。

```text
gain(x) = Σ w[t] · (Q[t](U ∪ {x}) - Q[t](U)) / Σ w[t]
```

`Q[t]` 是目标关卡的准备度估计，`Q[t](U)` 是不招募时的基线。先为已有角色生成少量种子队伍，再把三个候选分别放入各个位置，去重后批量交给 Critic。每个候选的评估池都保留原种子队伍，因此共用同一份基线。

- **单队目标**：取池中最高预测胜率。第三层配置为一队时、以及所有 EX，都走这一规则。
- **三队目标**：在池中搜索至多三支互不重人的队伍，结合最佳单队与多队储备打分。

常规评估中，三队准备度为：

```text
H = (最佳单队胜率 + 最佳互斥组合的胜率之和 / 3) / 2
Q = 0.8 · H + 0.2 · 生存覆盖度
```

生存覆盖度是“坦克数达标比例”和“治疗数达标比例”的平均值，上限各为 1。通常目标为三个坦克、两个治疗；守护遗物达到阈值时坦克目标降到两个，有治疗遗物时治疗目标降到一个。职能和遗物能力来自游戏数据。这个三队评分是用于排序的启发式指标。

EX 使用统一的网络评分，没有按关卡名称单独写选人规则。同一种 EX 的各楼层共用一个权重，只评估后续可能遇到的一个楼层版本，避免重复累计。

## 4. 商店：子集枚举 + 期望动态规划

因为刷新后商品不确定，商店决策是一个期望最大化问题。

当前页商品已知，刷新后的商品只知道分布。商品得分由配置给出，按商品计分。目标按字典序比较：先最大化期望得分，同分再最小化购买与刷新的总花费。

状态为：

```text
(已刷新次数 r，可用金币 g，已购买固定遗物的位掩码 M)
g = 当前金币 - 必须保留的金币
```

对当前页枚举所有购买子集 `S`，只保留买得起、且没有重复购买固定遗物的方案。每个子集比较两个转移：

```text
关闭：当前购买得分
刷新：当前购买得分 + 下一页最优得分的期望
```

下一页会先展示商品再选择购买，因此对每种可能页面分别求最优，再按概率加权。将状态 `(r,g,M)` 的期望结果记忆化，避免重复计算。当前实现最多考虑两次刷新；若刷新既不能提高得分，也不能在同分时减少花费，就关闭商店。

随机遗物用星级概率构造分布。若有 `s` 个随机槽位，只需枚举 `(一星数,二星数,三星数)`，共 `C(s+2,2)` 种组合，并用多项分布计算概率；三个槽位对应十种组合。这里假设各随机槽位独立。

第四层的固定遗物沿用当前价，未买的保留到后续页，买过的通过位掩码排除；印记按配置重新出现。未来印记和随机遗物的价格由当前随机印记价推断统一折扣，无法得到一致折扣时只规划当前页。

设每页最多有 `m` 件商品，购买子集构造为 `O(m·2^m)`。记包含当前决策的可达状态数为 `T`，每次预测的页面种类上界为 `D`，DP 共需约 `T·D·2^m` 次子集比较，另有记忆化表的查找开销。

项目里各层商店刷新的遗物星级概率均为统计结果。

## 5. 刷分：线性计分 + 阈值

按击败最后一个首领后的状态补齐计数：首领通关数加一，最后一层踏破格子数加一，并计入该层完成分。

```text
基础分 = Σ(各层踏破格子数 × 该层格子分 + 该层完成分)
       + 角色数 × 角色分 + 遗物数 × 遗物分
       + 普通通关数 × 普通分 + EX 通关数 × EX 分
       + (已击败首领数 + 1) × 首领分

预测分 = floor(基础分 × 难度倍率)
```

分值和倍率从游戏数据读取。例如五层流程已击败一个首领时，最终按两个首领计算。预测分 `>=` 当前公会目标就继续战斗，否则返回撤退重开的决策。

## 6. 自选、印记、遗物与事件：直接比较

| 类型 | 选择规则 |
| --- | --- |
| 开局自选 | 配置角色池与实际候选取交集；多于所需人数时均匀随机抽取，不足时无动作 |
| 普通自选券 | 按配置优先顺序扫描，选择当前可选角色，取够要求人数 |
| 印记三选一 | 按“属性优先级、票 ID”作字典序比较，取较大者 |
| 遗物三选一 | 按“星级、类别优先级、印记数量、已有同类印记总数、遗物 ID”依次比较，取较大者 |
| 事件（含老虎机） | 根据事件 ID 查配置选项，再检查原生选项条件；未配置或条件不满足则交给手动处理 |
